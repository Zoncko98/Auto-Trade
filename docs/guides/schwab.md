# Schwab developer API and OAuth authorization

**[Documentation](../README.md) | [Security](security.md) | [Operations](operations.md) | [Troubleshooting](troubleshooting.md)**

**Important:** Auto Trader is not affiliated with Charles Schwab. The installer never asks for the **Schwab website username or password**. Users sign in only through Schwab's hosted OAuth flow and should review Schwab developer eligibility, API terms and permissions themselves.

## First-time credentials

1. Register/obtain approval for an application in the official Schwab developer program.
2. Keep the **APP KEY**, **APP SECRET** and registered HTTPS loopback callback (example `https://127.0.0.1:8182`) available privately. The callback must match your actual Schwab app registration.
3. Run the first-time Auto Trader installer and select the optional Schwab developer configuration step. The wizard stores app credentials in `<DATA>/config/schwab.env` with restricted file permissions.
4. **Do not use your Schwab website password** in this wizard, Docker env file, source code, issue, screenshot or chat log.

## Separate authorization (no trading)

From the local Git checkout, replacing the sample data path:

```sh
docker compose \
  --env-file /mnt/POOL/apps/auto-trader-data/config/compose.env \
  -f deploy/docker-compose.yml \
  --profile live run --rm --no-deps --interactive --tty \
  --entrypoint python live-trader /app/schwab_oauth.py
```

This runs a **one-off authorization helper**, not the live trading worker. It guides you through Schwab's browser login and asks for the resulting redirected URL. The OAuth token is stored privately at `<DATA>/state/schwab_token.json`. Do not commit, email or publish this file. Back it up securely.

The helper refuses to overwrite an existing nonempty token automatically. Refresh/reauthorization and token recovery need a separate, controlled procedure.

## Safety gates

Creating an app and authorizing it does not enable trading:

- `LIVE_TRADING=false` is generated by the installer, and the live profile is not started.
- A **pinned account hash** (verified against broker account listings) is required for the current live worker.
- A read-only account/positions/orders/quote preflight must succeed.
- The trading risk controls enforce cash-only, long-only, valid limit orders, cap limits and reconciliation.
- Dashboard run/pause state is independent of the OAuth authorization.

**Do not use the optional Compose `live` profile or change `LIVE_TRADING` until you have separately reviewed brokerage account selection, authorization, order limits, account risk and testing.** This guide intentionally contains no one-command method to enable live execution.

## Data security

Protect the `config/` folder, `state/schwab_token.json` and `state/live/` ledger. Use encrypted backups, host filesystem ACLs and a private network. Logs and support reports should be checked before sharing.

If authorization fails, consult [troubleshooting](troubleshooting.md). Never post credentials, access tokens, callback URLs containing OAuth authorization codes, or real account identifiers.
